# Backup Pilot

Учебный менеджер резервного копирования для **Astra Linux Special Edition 1.8 x86-64**.
Кейс 04, проектный практикум МТУСИ. Имя будущего Debian-пакета и команды: `backup-pilot`.

**Текущий статус (28.10.2026):** подготовлены репозиторий, архитектурная схема, план,
задачи и правила работы. Приложение, его тесты и `.deb` ещё предстоит реализовать.
Зелёная проверка структуры репозитория не означает готовность продукта.

## Что должен уметь продукт

- Профили: источник, назначение, исключения.
- Резервное копирование по расписанию через systemd timer.
- Dry-run без изменения файлов и служебных данных.
- Retention старых версий с ограничением областью конкретного профиля.
- Контрольные суммы и выявление повреждений.
- Восстановление в отдельный каталог по умолчанию.

Единый CLI — основной интерфейс. Графический интерфейс, облака, шифрование и
инкрементальные копии не входят в обязательный объём первой версии.

## Работа с ветками

```text
dev → feature/BP-04-cli → PR в dev → ревью другого участника → merge в dev
dev → PR в prod → повторное ревью другого участника → merge в prod → release
```

`prod` — основная стабильная ветка; `dev` — интеграция разработки.
Код пишем в коротких ветках от `dev`. Прямые push в `dev` и `prod` запрещены,
включая администратора. В `prod` принимаются PR только из `dev` этого репозитория.
Нужны одно одобрение другого участника, успешные обязательные проверки и закрытые обсуждения.
После изменения кода одобрение требуется заново. Правила — [CONTRIBUTING](CONTRIBUTING.md).

1. Принять приглашение в репозиторий; получить доступ с правами Write.

4. Работать по одной задаче в отдельной ветке, связать PR с issue и запросить ревью.

GitHub используется для разработки и задач по просьбе команды. Задание требует также
исходники и работающий `lint → test → package` в **GitFlic**: это отдельная обязательная
задача BP-23, а не выполненная часть проекта. Финальные ветки и теги должны совпадать на обеих площадках.

Сейчас GitHub Actions проверяет структуру репозитория и направление PR.
`gitflic-ci.yaml` — исходный шаблон; продуктовые `scripts/lint.sh`, `test.sh`, `package.sh`
пока явно завершаются ошибкой «не реализовано». Продуктовый CI включается после появления
работающих локальных команд; пустые тесты не должны считаться успешной приёмкой.

## Будущая установка

`.deb` пока отсутствует. После реализации и проверки на чистой Astra ожидается:

```sh
sudo apt install ./dist/backup-pilot_<version>_amd64.deb
backup-pilot --help
backup-pilot --version
dpkg -L backup-pilot
sudo apt remove backup-pilot
```

Рабочие примеры будут подтверждены реальным пакетом в BP-24 и BP-26.
Пользователю не должны требоваться каталог исходников, dev-venv или Интернет после установки.
