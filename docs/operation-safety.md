# Защита операций (BP-16)

execute_backup и apply_retention используют один profile_lock(profile).
Lock освобождается ОС при аварийном завершении процесса, постоянный файл
не удаляется. Второй процесс получает код 6 до изменения snapshot.
Предварительный план строится без блокировки и записи; выполнение проверяет
файловые сигнатуры повторно под блокировкой. Ошибка сохраняет partial для
диагностики; только завершённая копия публикуется атомарным rename.
Контракт для BP-15: весь restore, включая повторный verify и публикацию новой
цели, выполнять внутри with profile_lock(profile); preview вне контекста.
