Целевая среда — Astra Linux Special Edition 1.8 x86-64. Сначала подготовить отдельную чистую

## Учебный стенд Astra SE 1.8 (BP-02)

**Статус:** технические критерии BP-02 проверены 05.11.2026 на установленной Astra.
Фактический вывод — `docs/evidence/bp-02-stand.txt`. Чистая загрузка проверена без
CD-привода; root находится на `/dev/vda2 ext4`. Ревью и слияние PR выполняются отдельно.

### Зафиксированная среда

| Параметр | Значение |
|---|---|
| ОС | Astra Linux Special Edition 1.8 x86-64, build `1.8.1.6` |
| Ядро | `6.1.90-1-generic` |
| Режим защищённости | `base(orel)`, mode 0 |
| Python | Python 3.11.2, `tomllib: OK` |
| systemd | 252 (`252.17-1~deb12u1astra.se1+ci13`) |

| Snapshot | `clean-install` — после установки с frozen ISO; `stand-ready` — после подготовки стенда |

### Подготовка ВМ

1. Создать ВМ x86-64 (на Apple Silicon — UTM в режиме эмуляции). Образ Astra SE 1.8 брать
   только из официального источника; в Git образы и диски ВМ не добавляются.
   Пример для UTM (QEMU): архитектура x86_64, машина q35, UEFI, 1 vCPU, 2048 МиБ RAM, диск VirtIO 30 ГиБ,
   CD-привод IDE, сеть «Emulated» с пробросом `127.0.0.1:2223 → 22` для SSH (`ssh -p 2223 ...`).
   В UTM здесь используются полные клоны остановленной ВМ как точки отката: `utmctl clone <UUID> --name clean-install`.
   Бинарник macOS: `/Applications/UTM.app/Contents/MacOS/utmctl`.
   Аналогично сохранить stand-ready после подготовки. Встроенный qemu-img.framework
   не является самостоятельной CLI-командой; для qemu-img нужен отдельный исполняемый файл.
2. Для этой конфигурации UTM потребовался `noapic`: без него возникал сбой IO-APIC timer.
   Дополнительный аргумент QEMU: `-machine i8042=on,hpet=on`. Штатный ISO сохранён без изменений;
   для загрузки Live использован производный ISO. Воспроизведение на macOS с Python 3.11+:

   ```sh
   python3 scripts/stand/make-utm-live-iso.py /путь/astra-se-1.8.1-amd64.iso /путь/astra-utm-live.iso
   ```

   Скрипт принимает только ISO с зафиксированным размером и SHA-256 (см. evidence), меняет две
   строки EFI GRUB с сохранением длины и не перезаписывает существующий output. В Live включены
   serial-консоль и root debug shell для диагностики. Этот ISO отключается перед приёмкой;
   в установленном GRUB остаётся только `noapic console=ttyS0,115200n8`, без debug shell.
3. Для диска 30 ГиБ выбрать шаблон разметки `minimal` (EFI 600 МиБ, остальное ext4);
   `default` требует не менее 40 ГиБ. Выбрать базовый режим Orel (mode 0), без графического
   окружения Fly. Установить `python3`, `openssh-server`, `git`, `sudo`, `qemu-guest-agent`
   и штатные `astra-safepolicy`, `parsec`; использовать generic-ядро Astra. Пакеты Parsec
   нужны и в Orel: конфигурация SSH использует штатные PAM-модули cap/aud/mac.
   Создать администратора стенда; пароли и SSH-ключи нигде в репозитории не указываются.
4. Завершить установку, перезагрузиться с диска без ISO и сделать snapshot `clean-install`.
   Источник пакетов этого стенда — frozen ISO 1.8.1.6; обновления из сети отдельно не проверены.
   Этот клон без исходников проекта используется для приёмки пакета (P1, BP-24).

На этом стенде установка была прервана на 37% и восстановлена без форматирования:
`dpkg --configure -a`, штатные пакеты с ISO (включая Parsec для PAM), GRUB UEFI и режим Orel.
Временные monitor/VNC и CD-привод удалены после диагностики. Режимы Voronezh/Smolensk,
Hardened-ядро и сетевые обновления на этом стенде не проверены.

### Учебный пользователь и данные

Администратор стенда — `bpadmin` (группа `astra-admin`, sudo с паролем); root заблокирован.
Учётные данные хранятся вне репозитория. Фактические скрипты на ВМ:
`/opt/backup-pilot-stand/prepare-stand.sh` и `collect-stand-info.sh`.

Скопировать на ВМ каталог `scripts/stand/` (или клонировать репозиторий в домашний каталог
администратора) и выполнить:

```sh
sh scripts/stand/prepare-stand.sh            # план, ничего не меняет
sudo sh scripts/stand/prepare-stand.sh --apply
```

Скрипт создаёт:

| Объект | Владелец / права | Назначение |
|---|---|---|
| пользователь `bpuser` | без пароля, без `sudo`/`astra-admin` | непривилегированный запуск, проверки отказа доступа |
| `/srv/backup-pilot-demo/` | `root:root`, 0755 | корень учебных данных |
| `/srv/backup-pilot-demo/source/` | `bpuser:bpuser`, 0750 | источник профиля `examples/profile.toml` |
| `/srv/backup-pilot-demo/backups/` | `bpuser:bpuser`, 0750 | назначение копий |
| `source/docs/readme.txt` | 0640 | обычный файл, должен попасть в копию (A1) |
| `source/notes.tmp`, `source/cache/item.txt` | 0640 | исключаются правилами `*.tmp` и `cache/**` (A1) |
| `source/bin/sample.bin` | 0640 | детерминированные 64 КиБ для побайтного restore (A4) |

Повторный запуск проверяет тип, владельца, группу и права существующих объектов.
При несовпадении скрипт останавливается и сообщает ожидаемое значение.
Подкаталоги и файлы в `source` создаёт непривилегированный пользователь.
Имя пользователя и корень можно переопределить через `BP_USER` и `BP_ROOT`.
У пользователя должна быть только одноимённая группа. Компоненты пути до `BP_ROOT`
должны принадлежать root и быть защищены от записи другими пользователями.
Работа от имени учебного пользователя: `sudo -iu bpuser`.

После подготовки сделать snapshot `stand-ready`.

### Проверка и фиксация

```sh
sudo sh scripts/stand/collect-stand-info.sh > docs/evidence/bp-02-stand.txt
```

Скрипт ничего не меняет и не выводит имя машины, сетевые адреса и учётные записи,
кроме `bpuser`. Перед коммитом всё равно просмотреть файл. Проверка считается пройденной,
если в выводе нет `FAIL` и `NOT FOUND`, `tomllib: OK`, права каталогов и файлов
соответствуют таблице, а SHA-256 файла `bin/sample.bin` равен
`7daca2095d0438260fa849183dfc67faa459fdf4936e1bc91eec6b281b27e4c2`.

Сброс стенда — остановить рабочую ВМ и использовать сохранённый клон `stand-ready`
(или `clean-install` для приёмки пакета). Не запускать исходную ВМ и её клон одновременно:
у них одинаковый локальный проброс SSH-порта.

Плановые пути установки и служебных данных — в `architecture.md`. Описать зависимости,
конфигацию `/etc/backup-pilot/`, пользователя службы, права 0700 на закрытые служебные каталоги,
установку/обновление/удаление, включение и остановку timer, просмотр journald, dry-run и откат расписания.
Пакет не включает и не запускает боевой профиль автоматически.

Remove не удаляет резервные копии и чужие данные. Purge затрагивает только явно перечисленные
файлы пакета; пользовательские копии сохраняются. Это проектная политика, которую нужно
подтвердить реальными maintainer scripts и испытаниями.

CI: сначала локально работающие `scripts/lint.sh`, `test.sh`, `package.sh`, затем GitHub Actions
и GitFlic `lint → test → package` с `.deb` в artifacts. Секреты — только CI variables.
На GitFlic должны присутствовать `prod`, `dev` и финальные теги с теми же SHA, что на GitHub.
Контейнерные проверки дополняют, но не заменяют испытания systemd/пакета на Astra-ВМ.
