## Runtime и зависимости

По архитектуре: Python >= 3.11, stdlib (argparse, tomllib, pathlib, shutil,
hashlib, json, unittest), systemd и системные Debian-инструменты. Runtime не
должен требовать pip-пакетов. Фактическая среда: Astra SE 1.8.1.6 x86-64, generic 6.1.90-1, Python 3.11.2,
stdlib/tomllib, systemd 252. Полный отчёт стенда — в PR #33 (`bp-02-stand.txt`).
В BP-05 статически обнаружены только импорты stdlib; динамических импортов и вызовов
внешних команд в шести Python-файлах прототипа не найдено. Фактический запуск проверяется
в режиме `-I -S`, без site-packages и переменной PYTHONPATH.

## Предварительная проверка

Под bpuser, где `/opt/backup-pilot-prototype` — отдельный checkout BP-05:

```sh
python3 -I -S scripts/stand/check-runtime.py --repo /opt/backup-pilot-prototype --probe-cli
```

Коды: 0 — пройдена только предварительная проверка; 1 — ошибка версии,
импорта/синтаксиса или CLI; 2 — отсутствует прототип/точка входа либо запуск вне
целевой Astra. Отсутствие прототипа никогда не выдаётся за PASS.

Скрипт не изменяет учебные каталоги. Статический анализ импортов приблизителен:
проверить динамические импорты и вызовы внешних команд вручную. --probe-cli
запускает только --help и --version с -I -S, исключая site-packages и PYTHONPATH.
В текущем BP-04 реализована точка входа `python -m backup_pilot`. Для запуска из src
проверка явно добавляет каталог src через runpy, сохраняя изоляцию `-I -S`.

## Сквозной сценарий BP-05

```sh
python3 -I -S scripts/stand/verify-prototype.py --repo /opt/backup-pilot-prototype
```

Скрипт требует Astra 1.8 x86-64, непривилегированный запуск, неизменённый checkout и
учебные данные BP-02. Вызывает реальный CLI: `--help`, `--version`, `profiles validate`,
`run demo`, `snapshots demo`. Создаёт настоящую копию в destination из examples/profile.toml,
сравнивает SHA-256 файлов, исключения и исходный source. Результат сохраняется на стенде.

Отдельная временная фикстура содержит читаемый `a.txt` и недоступный `z.txt`: реальный
`run` должен вернуть код 3 после создания частичной копии. Скрипт проверяет отсутствие
success metadata и пустой список завершённых snapshot. Это фактический отказ файловой
системы, без подмены реализации backup. Временная фикстура удаляется после проверки.

Ручная проверка результата:

1. Записать полный git SHA исходников и версии стенда. Изучить фактический --help;
   используемые команды должны совпадать с checkout, указанным в отчёте.
2. Скопировать examples/profile.toml в доступный bpuser учебный путь и выполнить
   фактическую команду валидации. Исходники и профиль должны быть доступны bpuser.
3. Сохранить SHA-256 source, выполнить один backup от bpuser и перечислить версии
   командой CLI. Записать команды, exit code и относительный путь новой версии.
4. Сравнить обычный readme.txt и sample.bin с source; notes.tmp и cache/item.txt
   должны отсутствовать. Убедиться, что source не изменён, snapshot завершён,
   а частичный результат не отображается как успешный.
5. Приложить обезличенный docs/evidence/bp-06-run.txt с ожидаемым и фактическим
   результатом каждого шага. Не сохранять чужие файлы и не отмечать NOT RUN как PASS.
