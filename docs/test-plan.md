## Автоматические проверки продукта

Unit: профили и glob-исключения; валидация путей/keep_last; план retention и границы профиля;
SHA-256; безопасное разрешение путей restore; отображение кодов ошибок.
Integration: `профиль → run → verify → restore → сравнение байтов → prune` в `TemporaryDirectory`.
Отказы: отсутствующий источник, запрет прав, недоступное назначение, повреждённый manifest/файл,
выход через `..`/symlink, неполная копия, недостаток места, конкурентный запуск.
Для отказов проверять не только код ошибки, но и сохранность исходных и чужих данных.
Тесты прав выполнять непривилегированным пользователем на Linux.

## Чистая контрольная Astra Linux

Зафиксировать Astra Linux SE 1.8 x86-64, версию Python/systemd, режим защищённости стенда,
версию пакета, commit/tag, дату, проверяющего и команды. ВМ не содержит исходников и dev-venv.
Проверить `.deb` из CI: apt install, `--help`, `--version`, `dpkg -L`, сценарии A1–A5,
таймер и отказ доступа, обновление с предыдущей учебной версии, remove и оговорённую политику purge.
Сохранять обезличенные логи/вывод в `docs/evidence/`, без пользовательских резервных копий и секретов.
