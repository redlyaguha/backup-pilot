## 2. Детальные сценарии тестирования (Acceptance Criteria)

### TC-A1: Исключение файлов (Glob-паттерны)
*   **Данные:** На стенде `bpuser` в `source/` есть `bin/sample.bin`, `cache/item.txt`, `notes.tmp`.
*   **Шаги:** Выполнить `backup-pilot run <profile>` с `exclude = ["*.tmp", "cache/**"]`. Перейти в `.../data/` снапшота.
*   **Ожидаемый результат:** Присутствует `bin/sample.bin` и `docs/readme.txt`. `notes.tmp` отсутствует. Папка `cache` может остаться, но она должна быть пустой (без файлов).

### TC-A2: Политика Retention (keep_last)
*   **Данные:** Сделано 4 завершенных снапшота. В конфиге `keep_last=2`. Рядом лежит чужой каталог.
*   **Шаги:** Выполнить `backup-pilot prune <profile> --apply`.
*   **Ожидаемый результат:** Осталось 2 последних снапшота. Самые старые удалены. Чужой каталог и `.partial-*` не затронуты. *(Без флага `--apply` команда `prune` должна лишь показать план).*

### TC-A3: Режим Dry-run
*   **Данные:** Настроенный профиль, существующий source. Проверяем run/prune/restore/schedule с dry-run.
*   **Шаги:** Зафиксировать `sha256sum` и `mtime` файлов, служебных данных и systemd. Выполнить `backup-pilot run <profile> --dry-run` (и другие команды с dry-run).
*   **Ожидаемый результат:** Exit code 0. В destination не появились папки `.partial-*` или новые снапшоты. Дерево, содержимое, метаданные, служебные данные и systemd не изменились.

### TC-A4: Побайтное восстановление (Integrity & Restore)
*   **Данные:** Снапшот с бинарным файлом `bin/sample.bin`. Эталонный SHA-256: `7daca2095d0438260fa849183dfc67faa459fdf4936e1bc91eec6b281b27e4c2`.
*   **Шаги:** Выполнить `backup-pilot restore <profile> <snapshot> --to /tmp/restore_test`. Сравнить `sha256sum` оригинала и восстановленного файла.
*   **Ожидаемый результат:** Exit code 0. Хэши совпадают побайтно. Исходные файлы не перезаписаны.

### TC-A5: Обнаружение повреждения (Integrity)
*   **Данные:** Завершенный снапшот с `manifest.json`.
*   **Шаги:** Изменить 1 байт в файле внутри `.../data/`. Выполнить `backup-pilot verify <profile> <snapshot>`.
*   **Ожидаемый результат:** Exit code 5. Вывод в stderr: "Integrity violation: hash mismatch".

### TC-ERR-01: Неверная конфигурация (Exit Code 2)
*   **Данные:** TOML-файл с `source`, содержащим `..` или symlink.
*   **Шаги:** Выполнить `backup-pilot profiles validate --config bad.toml`.
*   **Ожидаемый результат:** Exit code 2. Вывод: "Invalid config: path traversal/symlink is not allowed".

### TC-ERR-02: Отказ доступа (Exit Code 3)
*   **Данные:** Запуск от `bpuser` на файл, у которого нет прав на чтение.
*   **Шаги:** Выполнить `backup-pilot run <profile>`.
*   **Ожидаемый результат:** Exit code 3.

### TC-ERR-04: Конкурентный запуск (Exit Code 6)
*   **Данные:** Запущен один процесс `run`.
*   **Шаги:** Запустить второй `run` того же профиля в другом терминале.
*   **Ожидаемый результат:** Exit code 6 (профиль занят).

### TC-S1: Запуск по таймеру systemd
*   **Данные:** Настроенный профиль, systemd timer.
*   **Шаги:** Дождаться срабатывания таймера на стенде.
*   **Ожидаемый результат:** В журнале (journalctl) успешный запуск, в destination появился новый проверяемый snapshot.

### TC-P1: Установка и удаление пакета
*   **Данные:** Чистая Astra без исходников.
*   **Шаги:** Выполнить `apt install` пакета `.deb` из CI.
*   **Ожидаемый результат:** Команда доступна из PATH; конфиги/копии сохранены по политике, чужие данные не затронуты. Проверены update/remove.

## 3. Автоматические проверки (Unit / Integration)
*   **Unit:** валидация путей/keep_last, безопасное разрешение путей restore, проверка SHA-256 по манифесту.
*   **Integration:** `профиль → run → verify → restore → сравнение байтов → prune`.
*   **Отказы:** Отсутствующий источник (exit 2), запрет прав (exit 3), поврежденный manifest (exit 5), конкурентный запуск (exit 6).

## 4. Дополнительные проверки и целевая среда

Unit: профили и glob-исключения; валидация путей/keep_last; план retention и границы профиля;
SHA-256; безопасное разрешение путей restore; отображение кодов ошибок.
Integration: `профиль → run → verify → restore → сравнение байтов → prune` в `TemporaryDirectory`.
Отказы: отсутствующий источник, запрет прав, недоступное назначение, повреждённый manifest/файл,
выход через `..`/symlink, неполная копия, недостаток места, конкурентный запуск.
Для отказов проверять не только код ошибки, но и сохранность исходных и чужих данных.
Тесты прав выполнять непривилегированным пользователем на Linux.

## Чистая контрольная Astra Linux

Зафиксировать Astra Linux SE 1.8 x86-64, версию Python/systemd, режим защищённости стенда,
версию пакета, commit/tag, дату, проверяющего и команды. ВМ не содержит исходников и dev-venv.
Проверить `.deb` из CI: apt install, `--help`, `--version`, `dpkg -L`, сценарии A1–A5,
таймер и отказ доступа, обновление с предыдущей учебной версии, remove и оговорённую политику purge.
Сохранять обезличенные логи/вывод в `docs/evidence/`, без пользовательских резервных копий и секретов.
